# 11. 로드맵과 단계별 완료 조건

[README](../README.md) · [현재 상태](../PROJECT_STATUS.md)

## 현재 위치

부서 이동 정상 경로는 단계별 함수 호출로 `DONE`까지 확인했습니다. 가장 최근 개발 방향은 **Worker로 넘어가기 전에 네트워크 구성과 접근통제를 먼저 정리**하는 것입니다. 아래는 후속 계획이며 구현 완료 목록이 아닙니다.

| 순서 | 작업 | 다음 단계로 넘어갈 조건 |
|---:|---|---|
| 0 | 최신 코드·DDL·장비 설정·`DONE` 기준선 보존 | 같은 버전의 코드, 상태, 검증 기록을 함께 식별 가능 |
| 1 | 장비 역할, VLAN, SVI, 라우팅·관리 경로 정리 | 현재 경로와 변경 대상이 문서·설정에서 일치 |
| 2 | VLAN별 접근 정책과 필수 통신표 확정 | 출발·도착·서비스·허용/차단·근거가 명확 |
| 3 | VLAN ACL을 한 구간씩 적용 | 허용·차단 시험과 인증·DHCP 확인 통과 |
| 4 | 필요한 경계 방화벽·DMZ·서버 구역 구성 | 우회 경로 없는 정책 적용과 로그 확인 |
| 5 | 기존 부서 이동 정상 경로 회귀 | VLAN21 → VLAN20 → DHCP 정리 → `DONE` 재확인 |
| 6 | Event Worker / State Dispatcher | 한 실행에서 현재 State에 맞는 다음 단계 하나만 진행 |
| 7 | 실패·재시도·타임아웃·오프라인 처리 | 장애 지점별 재실행·보류·종료 규칙 검증 |
| 8 | HR Workflow systemd timer | 중복 실행 방지·관측·실패 알림·주기 실행 검증 |

네트워크 전체 장기 목표를 모두 끝내야 Worker를 시작하는 것으로 고정하지 않습니다. 실제 도입 범위가 정해진 네트워크 변경을 완료하고 회귀 검증한 뒤 자동화 개발로 복귀하는 흐름입니다.

## Worker의 다음 목표

- Event의 현재 State를 읽고 대응하는 단계만 선택.
- 이미 완료한 단계에 대한 재실행 결과를 명확히 처리.
- 외부 요청 전후 상태와 결과를 남겨 불확실한 실행을 식별.
- 작업자 중복 실행·잠금·장애 종료에 대한 정책 구현.
- `ERROR`, Retry, `TIMEOUT`, `SUPERSEDED`, Offline User를 정상 경로와 구분.

## 장기 확장

| 주제 | 검토할 내용 | 현재 상태 |
|---|---|---|
| 퇴사·비활성·HR 삭제 | 신규 인증 차단, 현재 세션 종료, 자원 정리의 전체 수명주기 | 후속 |
| MAB | 비802.1X 단말의 등록·승인·소유자·접근 정책 | 후속, DHCP 관찰만으로 자동 신뢰 등록하지 않는 방향 |
| IDS·중앙 모니터링 | 네트워크·서버·인증 로그의 연계와 탐지 | 후속 |
| Core HA | Gateway VIP와 Relay 주소 매핑, 중복 경로, 장애 전환 | 후속, 기존 DHCP 증거 흐름과 함께 검증 필요 |
| DHCP 현대화 | 기존 설정·예약·상태 모델을 Kea로 옮기는 범위 | 검토 후보 |
| 성능 검증 | 다중 사용자·지연·처리 시간·실패 복구 측정 | 미측정 |

ISC는 ISC DHCP 유지보수를 2022년 말 종료했다고 안내합니다. 이 포트폴리오는 기존 ISC DHCP 랩의 구현 기록이며, Kea 전환 완료를 의미하지 않습니다. [ISC 공식 안내](https://www.isc.org/dhcp/)

## 다음 공개 마일스톤

최신 랩의 Event DDL, Action Log, 단계별 함수와 검증 자료를 동일 버전으로 정리한 뒤 현재 Repository에 반영할 예정입니다. 구현이 확인되지 않은 기능은 완료 항목으로 표시하지 않습니다.
